# برنامه‌ی ویدئوی دمو (حدود ۵ دقیقه)

هدف: یک داستان واقعی را نشان بدهید؛ از «یک فایل zip دارم» تا «چیزی خراب شد، دستیار علت را پیدا کرد و من راه‌حل را تأیید کردم». خروجی را نشان بدهید، نه کد را. آرام و واضح صحبت کنید.

## قبل از ضبط (حدود ۱۵ دقیقه، یک‌بار)

1. `npm run dev` را اجرا کنید و `http://localhost:3000` را باز کنید. در پنل مدیریت ← تنظیمات و اتصال‌ها، «تست اتصال» لیارا و هوش مصنوعی هر دو باید سبز باشند. کلیدها ماسک‌شده‌اند؛ فایل `.env.local` را جلوی دوربین باز نکنید.
2. این پروژه‌ها را از قبل از مسیر **ساخت برنامه** و با zipهای پوشه‌ی `test-projects/` دیپلوی کنید (هر ساخت ۲ تا ۴ دقیقه طول می‌کشد). نام‌ها فقط پیشنهادند:
   - `healthy-app` ← برنامه‌ی `demo-ok`
   - `wrong-port` ← برنامه‌ی `demo-port` (ویزارد آن را با پورت ۳۰۰۰ می‌سازد؛ مشکل همین است)
   - `memory-heavy` ← برنامه‌ی `demo-memory` (روی کوچک‌ترین پلن مدام کشته می‌شود)
   - `memory-leak` ← برنامه‌ی `demo-leak`
3. ۶ تا ۱۰ دقیقه صبر کنید تا حالت «در حال راه‌اندازی» تمام شود و پایش داده‌ی واقعی داشته باشد. روی هر برنامه یک‌بار «بررسی عملکرد» را بزنید تا لاگ هوش مصنوعی پر شود.
4. پروژه‌های `fullstack-todo` و `flask-no-requirements` را از قبل نسازید؛ این دو را زنده نشان می‌دهید (ساخت چندبخشی حدود ۵ دقیقه طول می‌کشد؛ بخش انتظار را ببُرید یا تند کنید).
5. بعد از ضبط، همه‌ی برنامه‌ها را حذف کنید (اعتبار مصرف می‌کنند).

## نکته‌ها

- اگر بررسی هوش مصنوعی بیشتر از ۱۰ ثانیه طول کشید، توضیح بدهید چه چیزی جمع می‌کند (لاگ، رویدادها، CPU و RAM، وضعیت release و درخواست زنده به سایت)؛ همین ارزش کار است.
- حتماً یک موردی را نشان بدهید که دستیار عمداً «درستش نمی‌کند» (نشتی حافظه). ثابت می‌کند دستیار یک ابزار کورکورانه‌ی رفع خودکار نیست.
- ماوس را آهسته حرکت بدهید و زوم مرورگر را روی ۱۱۰ تا ۱۲۵ درصد بگذارید.
- `.env.local`، فایل `.data/state.json` و توکن‌ها را نشان ندهید.
